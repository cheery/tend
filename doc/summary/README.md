# doc/summary/ — two sheets, and what keeps them honest

Two one-page summaries of tend, and the mechanisms that stop them
rotting quietly.  Asked by Henri, 2026-08-25: *"Save them into
doc/summary/ ... make something that ensures they're kept updated."*

## The files

* [rules.md](rules.md) — **Sheet 1**, the fifteen invariants a session
  works under, each tagged with the mechanism that enforces it.
* [interfaces.md](interfaces.md) — **Sheet 2**, the human-facing
  surface by kind: the keys, the instruments, what the tree says back,
  the plain files, and the one outward cord.
* `tend-sheets.html` — the same two sheets, styled and **printable as
  A4** (two pages).  The markdown is canonical — plain files a person
  reads without a browser (`vision.md`); the HTML is the rendering, and
  is regenerated by hand when the markdown changes — and
  `tools/sheets.py` says where it has not been: every heading and every
  tree file or card a sheet names must be in the twin, and the other
  way round, and a chip beside a card must agree with the card's shelf
  (Henri, 2026-08-27: "make a checker for the tend-sheets.html", the
  hour after the twin said "not built yet" about a card in `done/`).

## What keeps them updated

A summary that can drift silently is a wish, so two instruments hold it,
split the way the rest of the tree splits hard from soft:

* **The gate — `test/test_summary.py`.**  Every tree path the summaries
  cite must exist, every `card:` they cite must resolve on some shelf,
  their one live claim — that the andon is built — must agree with
  `card:cords.md`'s shelf in both directions, and the twin must pass
  `tools/sheets.py`.  Rename a tool, move a card, or let the HTML lag
  the markdown, and the commit is refused until the summary is
  reconciled.  This is correctness; it blocks.

* **The lamp — `tools/summary.sh`.**  It lights when a mechanism the
  summary describes has a commit newer than the summary's own — the
  prose *may* have gone stale and wants re-reading.  It cannot grade
  prose (no test can; the kaizen lamp has the same honest limit), so it
  informs and never blocks.  It clears when `doc/summary/` gets a newer
  commit — a re-confirm, even unchanged, is enough.

  Run it by hand, or, if you want it at every prompt, add
  `tools/summary.sh --hook` to `UserPromptSubmit` beside the others —
  that edit is yours, because hook config is enforcement.

*So the sheets cannot cite something that no longer exists (the gate),
and cannot fall behind a changed mechanism without saying so (the
lamp).  Neither can make the prose true — that is a reader's job — but
neither lets it be silently false.*
