*Henri, on the evidence in `doc/mediation-order.md`: "Could we in any
way examine both options?  You're really fast and everything is maybe
reversible."  So both were tried the same hour, each as a fence script
beside this file and a list of what it complained about.  The reading

## The two trials

**Sessions first** — `2026-08-25-sessions-first-fence.sh`: the reach
fence of the morning (`2026-08-25-reach.md`) plus the two rows that
record said a session cannot do without: `~/.local/state` and the
sitting's state file passed through read-write, and one named tree
(gestate) read-only.  `DISPLAY` scrubbed.  The principal under it is
this session's own work.

**Programs first** — `2026-08-25-programs-first-fence.sh`: a node with
exactly the three nouns `doc/mediation-order.md` wrote for it — its
bundle read-only, audio out, its own state directory read-write — and
nothing else: no other tree, no `/run`, an empty home.  The node is
gestate's andon (`python -m gestate.audioperform tools/andon.ges`),
which is also the cord `card:cords.md` says tend needs.  Its reach
was traced unfenced first: `/dev/snd/*`, the PipeWire socket, a probe
at a JACK socket and at `nscd`, its bundle; its "own state file" is
the `-o` render.

**Zero complaints, and that is the finding.**  Traced, the
`/dev/snd`-only ring opened **`pcmC0D0p` directly** — the hardware,
past PipeWire — and while enumerating it opened **`pcmC0D0c`, the
capture device, three times.**  So "audio out", the first of the
node's three nouns, is not a noun the kernel has.  `/dev/snd` is the
card: out, in, and the mixer.  The narrower grant is the PipeWire
socket, which is "audio, mediated by the server" — and still both
directions unless the server's policy says otherwise.  The node's
vocabulary worked on the first try because its first word quietly
meant more than it said.

## What the two trials say together

**They are one script.**  Programs-first is sessions-first with two
rows off (the tree writable, the state passthrough) and one on
(audio).  Both fences are `bwrap` with binds — which is *exec with
grants*, the session's vocabulary — and the node ran inside a fence
the session wrote and started.  `doc/mediation-order.md` §2 said on
paper that the node's nouns are the session's list as a degenerate
case; today they were, in a shell script.

**So the order question has changed shape.**  It is no longer *which
vocabulary* — there is one, and its rows are the morning's table with
"audio" split by what the trace showed.  It is *which principal gets
a caller outside the session's write access first*:

* For **sessions**, that caller is a hook — gestate's
  `tools/fence-hook.sh` on `PreToolUse` for `Bash` is the shape — and
  on this tree hook config is Henri's, which is exactly the property
  wanted.  Cheap, precedented, and the session cannot install it for
  itself.
* For **programs**, tend has no program of its own yet; the andon is
  gestate's and was launched by a session.  A node fence with nobody
  outside the session to start it is the same decoration as a session
  fence the session starts.

**What kills each**, stated so the choice stays open:

* *Sessions-first dies* if the daily work has a reach the rows cannot
  name — none found in the morning's thirteen runs or this trial's
  eleven, bar the bus, which degrades out loud — or if the hook cannot
  wrap a session's commands without breaking them, which is untested
  here.
* *Programs-first dies* if tend goes months without a program of its
  own to govern (true today), or if the node's nouns turn out to need
  the session's anyway — which they did, twice.

**A session's reading, suspected**: the two orders converged into one
fence with a dial, and the first outside caller is the hook for
sessions, with the andon the first node under it when `cords` comes
off the shelf on 2026-08-31.  That is not a decision; it is what the
two scripts beside this file look like when put next to each other.
