# 2026-08-24 — does the leash catch the flare?  It could not be made to happen.

*The keep-or-revert experiment `card:work-environment-ai.md` §"Day one"
named for `tools/leash.sh`, run by a session on the afternoon Henri
said the machine was free.  Everything measured is below; the reading
is a session's and suspected.*

## The question

On 2026-08-18 a session running a full fenced suite, `cargo`, two X
servers and twelve polling shells made the sound tear on the machine
Henri was listening on (`~/gestate/journal/2026-08.md` §"And what a
session costs the machine").  The leash was built for that caller.  The
test: play a piece on gestate's C host, run that load beside it
unleashed and leashed, and read the underrun counter (`host.dry`) both
ways.  Where the unleashed run flares and the leashed one stays quiet,
the leash has caught the case.

## What was measured

Probe: gestate's `Workbench` on `examples/audio/minute.ges`, 44.1 kHz,
256-frame blocks (5.8 ms each), the counter read before and after.

| condition | seconds | card dry | worst block |
|---|---|---|---|
| machine idle | 30 | 0× | 0.5 ms |
| 8 busy loops (4 cores, 2× oversubscribed) | 35 | 0× | 2.7 ms |
| gestate's fenced `suite.py` + warm `cargo test`, together | 60 | 0× | 0.6 ms |
| cold `cargo build` (scratch target) + fenced suite + 12 polling shells | 90 | 0× | 2.7 ms |
| 8 spinners + 4 fork storms + 2 `dd` writers with fsync | 40 | 0× | 3.3 ms |

**The flare did not reproduce under any load.**  The worst block crept
toward the period and never crossed it; the host's 30 ms device latency
is several blocks of slack on top.

And the budget, measured on its own: four spinners for ten seconds
consumed **30.8 CPU-seconds free and 10.1 under `-c 100`** — the quota
binds to the number asked for.

## Why it did not reproduce — candidates, none confirmed

* **The load is not the load.**  Gestate's suite now finishes in about
  a minute where the journal entry describes twenty-five; the cold
  build of this four-crate workspace is thirteen seconds.  The commands
  are the same and the cost is not.
* **No X servers**, and no editor doing audition rebuilds beside the
  player.  `journal` §"It pops and crackles *while compiling*" is an
  in-process mechanism — GC pauses in the editor's own interpreter —
  which a probe that never rebuilds cannot provoke.
* The C host asks for no realtime priority (`host.c` has no
  `sched_setscheduler`), so scheduling is ordinary CFS, which turns
  out to protect a thread that sleeps most of its period rather well.

## What it means for keep-or-revert

The named criterion — *does it catch the case that already happened* —
cannot be scored, because the case no longer happens on demand.  So the
leash stays **tolerated, not owned**, on a different criterion that
Henri set the same afternoon: containment is measured by *how far would
it reach*, not by incidents (`card:work-environment-ai.md` §"It is
open").  On that criterion the day bought two things: the budget binds
(above), and the leash's kill now takes the orphans with it
(`test_leash.py::test_the_kill_takes_the_orphans_too`) — a gap found
while planning the first real run, which is the incident's
polling-shell shape and would have been invisible in a run that never
timed out.

## Two mistakes the session made, kept because they are the finding

* **`pkill -f 'while :; do'` killed the shell that ran it**, because
  the pattern was in that shell's own command line.  This is the
  2026-08-18 `pgrep -f "no:randomly"` bug exactly, made again by a
  session that had read about it an hour earlier.  Bracket the first
  character (`'[w]hile :; do'`), always.
* The first "real load" was too light to bite and was believed for a
  moment because it was real.  A load is a number, not a name.

## Repeat it

The probe, run from `~/gestate`:

```python
import os, sys, time
os.chdir("/home/cheery/gestate"); sys.path.insert(0, "/home/cheery/gestate")
from pathlib import Path
from gestate.audioeditor import Workbench
piece, seconds = Path(sys.argv[1]), float(sys.argv[2])
bench = Workbench(piece, rate=44100, block=256); bench.start()
end = time.time() + 60
while bench.live is None and time.time() < end: time.sleep(0.05)
time.sleep(1.0); host = bench.host
dry0, _ = host.dry, host.take_worst()
time.sleep(seconds)
dry, worst = host.dry - dry0, host.take_worst(); bench.stop()
print(f"[probe] {seconds:.0f}s · card dry {dry}× · worst block {worst/1000:.1f} ms of 5.8 ms")
```

The incident-shaped load, started with `setsid` so one `kill -- -PGID`
reaps all of it:

```sh
cd ~/gestate
CARGO_TARGET_DIR=/somewhere/scratch cargo build --workspace &
python3 tools/suite.py &
i=0; while [ $i -lt 12 ]; do (while :; do pgrep -f "no:randomly" >/dev/null; sleep 0.5; done) & i=$((i+1)); done
wait
```

What a future run should add, if the flare is wanted rather than
assumed: the editor auditioning beside the player (the in-process
mechanism), an X server, and a heavier tree than this one.
