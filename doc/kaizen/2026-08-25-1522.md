# Kaizen, 2026-08-25 15:22 — problem 1, enforced once, the boundary kept outside the program

*Written because the lamp lit on `a6a58b6`.  Henri: "go with A", after
asking for the cost/benefit of the two shapes.*

## What the sitting was

`card:keep`'s first enforcement.  Measured that Landlock is available at
ABI 4 from inside the fence — unprivileged, no build — and built
`tools/keep.py`: a launcher that grants a program read on only the paths
it is handed (plus the system roots to run), restricts itself one-way,
and execs.  A program under it reads its granted file and is refused the
file beside it, the tree, and the leash ledger.  Problem 1 — "how are
users' data protected from programs?" — enforced for the first time.

## What went right

**The decision was made on the tree's own rule, not on size.**  Henri
asked for cost/benefit; the honest comparison found that a program
confining itself breaks Rule 1 exactly as a session fencing itself
does — the boundary must be set from outside the bounded party.  So A
was not the smaller choice, it was the correct one, and the write-up
said so rather than listing tradeoffs flatly.  He chose on that.

**Measured before building, and the measurement paid twice.**  Landlock
ABI 4 was confirmed with a real syscall, not the manual — and the same
probe caught a second thing: raw bwrap and unshare *do* nest from inside
the fence, against `sandbox.sh`'s comment.  Recorded as its own line,
not folded into this card.

**The failing test was a finding, not a defect.**  The venv python could
not read its own `pyvenv.cfg` under keep — because the tree was not
handed to it.  That is the capability model working: a runtime is a
grant like any other.  Kept as a finding on the card and a note in the
test, not patched away by widening the grant.

**keep refuses rather than run unconfined.**  The Rule 9 shape from the
leash, carried: a grant that silently became "everything" is the one lie
the tool must not tell, so absent Landlock it does not exec at all.

## What went wrong, named as the session's

**The first "still runs" test reached for the interpreter running the
suite** (`sys.executable`, the venv) without thinking about what that
interpreter reads at startup.  The suite caught it in seconds, but the
lesson is the keep tool's own: a confined program's *runtime* is part of
what it must be handed, and the test author forgot the very thing the
tool exists to make explicit.

**keep binds nothing yet.**  It is a capability with no caller, the
leash's shape before the hook.  Built and demonstrated is what the card
owed, but the sitting should not let "enforced once" read as "the node
is confined" — it is not, until run through keep.  The card says so; the
kaizen says so louder.
