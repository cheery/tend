## What the sitting's tail was

`make PATH` became a grant word so the GPU driver's cache has a
directory before exec — the driver will not make one and caches
nothing without it — and `llm/grant` took the three lines.  By hand
the second start went 1:22 → **0:11** with eight entries.  Under keep,
run *one* filled the same eight and run *two* loaded at 1:21 and wrote
two more buckets: not a refusal — the cache was read and written — but
a **miss**; the key differs between one run and the next under keep and
not by hand.

## What went right

**The measurement was run twice, once on each side of the boundary,
before anything was believed** — and the by-hand number was recorded
on the card before the keep number came in, so the miss is a fact with
two sides rather than a disappointment.  The mtimes in the cache
directory told miss from refusal without a debugger.

## What went wrong, named as mine

**`make` landed with its test in the same commit, not shown red
first**, at six minutes on the clock; said on the card and here.  The
rule is red first, and the clock is not a reason — the line could have
waited for the next sitting.

**The measurement script I gave assumed a runner stops between pulls;**
pull *two* at 100 s found *one* still up and started nothing, which
cost Henri a third pull and me a minute reading which run was which.
A script that measures two starts should wait for `stopped`, not for a
number of seconds.
