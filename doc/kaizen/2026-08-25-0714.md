# Kaizen, 2026-08-25 07:14 — the hook, installed, and the first hour under it

*Written because the lamp lit on `0280c90`, and kept lit on purpose
until the first commands had run under the hook.  Henri said "show me
the hook", then ran the installer against a hook that did not exist,
which was the word; then ran it again when it did.*

## What the sitting was

`tools/sandbox.sh` and `tools/fence-hook.sh` built, tested, committed
before the install so a fix never had to come from inside a broken
fence.  Installed.  The first command under it escaped.  The hole
closed, `.claude/` made read-only inside, and the fence card's
demonstration happened: the two routes that went through this morning
fail from a fenced shell.

## What went right

**Committed before installing.**  When the first hook version had a
hole and the session had removed the hook line, nothing was stuck:
the shell was unfenced, the Edit tool was outside the hook's reach
anyway, and the fix was three edits and a suite run.

**The gate refused a commit inside the fence**, because the fence's
own tests failed there (it cannot nest).  Not a bug in the gate — the
tree disagreeing with itself, said out loud — and the answer was
skips that name themselves, not a weaker gate.

**The `.claude` bind was an afternoon's idea that took one line**, and
it is the card's demonstration.  A listing inside the fence showed
`settings.json` writable; ten minutes later it was not.

**`sh -n`, every time now.**  Both scripts, before every run.

## What went wrong, named as the session's

**The first command under the hook ran unfenced, and the session did
not notice until the output said `TEND_FENCED=unset`.**  The hook's
skip matched the fence's name anywhere in the command; the command
mentioned it.  Gestate's hook carries a paragraph about exactly this
shape — a pattern matching a *position* it did not mean — and the
session read that paragraph in the morning and wrote the same bug in
the evening.  Reading a warning is not applying it (yesterday's
kaizen said this about a different warning).

**Restored from a HEAD that did not have the hook line.**  The
settings commit had been refused a minute before; the session's
probe-and-restore command was written as if it had landed.  Result:
Henri's install undone by the session, silently, until the next
command's listing showed `PreToolUse: absent`.  A restore is only a
restore when HEAD holds what you mean; check `git log` for the file
first.  This is the second time today a session-written line quietly
worked against a person's edit.

**"exit 0" printed after every probe** in that measurement, because
`$?` was `tail`'s.  The error messages carried the truth anyway; the
exit codes in the transcript are wrong and a reader should not trust
them.

## What should change tomorrow

1. Before any `git checkout HEAD -- FILE`, `git log -1 -- FILE` and
   say what HEAD holds.  A restore that removes a person's edit is not
   a restore.
2. A hook's skip rule is tested for *what it must not skip* before
   what it may.  The five shapes in `test_fence_hook.py` are that list;
   add to it the day something escapes.
3. The count for the next kaizen: commands run under the hook, and
   how many needed a row.  So far, after the fix: zero rows asked for.
4. Henri decides `TEND_REACH_ALLOW` — which rows a session may ask
   for at all.  Until he sets it on the hook's line, none.
