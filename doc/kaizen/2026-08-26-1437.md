## What went right

**Reading the node before building found the blocker.**  A runner
served only pulls after its open; an outside resolver starts after the
pull.  The one-line change (`seen = state.pulls`) was the whole
enabling step, and it is a better rule than the old one — "starts by
pull" is now literally what happens — and a row breaks it.

**The double start was measured, not reasoned.**  Two back-to-back
looks both said "started one"; the tally was right (the second runner
hit the lock) and the resolver's word was wrong.  The wait-for-lock
loop exists because of that run, and a row removes it.

**The patch carries its test; the tree is green.**  Same as the state
row, one lesson later than the launcher.

## What went wrong, named as the session's

**Two tests failed for one omission I had already made once today.**
`resolve.sh` started `run.sh run` without `--idle`, so the runner idled
30 s and the tests waited 6.  `run.sh pull` had learned `TEND_NODE_IDLE`
at 13:29; the resolver, written by the same session five hours on, did
not carry it.  The countermeasure is not memory: the runner's idle is a
property of the launcher, and a caller that starts the launcher should
not have to know it.  Named for the `run.sh` patch after this one —
`run` reads `TEND_NODE_IDLE` itself — so no third starter can forget.

**The node test was moved rather than replaced.**  `test_it_opens_
where_it_was_left` asserted the old rule; I changed its numbers and
its docstring.  Right, and the minimum; but a test that asserted
"a pull before the runner is served" by name would be a better
detector than one that asserts 2 where it used to assert 1.  The row
covers it; the test's name does not.
