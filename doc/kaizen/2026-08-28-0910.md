## What the sitting was

* **The cache miss, read from an strace and fixed** (`ab63bc1`).  One
  run with `strace -f` on the program line — his pull, the session's
  read of `$STATE/strace.log` through the fence — showed the GPU
  driver writing each cache entry to a temp file in the cache root and
  renaming it into a bucket directory: `rename` → `EXDEV`, every time,
  because a Landlock ruleset that does not handle `REFER` refuses every
  cross-directory rename.  `keep` handles `REFER` now and grants it
  beneath `--write`; red first with a raw `rename(2)` (`mv` copies on
  `EXDEV` and would have hidden it).

  run wrote thirteen real cache entries and the second start read them
  — 1:20 cold to 0:12 warm, matching the 0:11 he saw by hand.  The
  whole chain is the tree's: `make` creates the directory, `env` points
  the driver at it, `keep` grants the rename.
* **The not-yet lifted** (`3bef67b`): `session-program` unblocked at his
  word, status `doing`, and the road to a node that leads work written

## What went right

**The one boundary bug was found by watching the program, not by
reasoning.**  Every guess about the cache (runtime broken, driver off,
key differs) was wrong; the strace showed the exact syscall and the
exact errno, and the fix was one handled bit with a red-first test.
The tool the tree already had — a program run under a grant, its state
readable through the fence — is what read it.

**Miss was told from refusal by mtimes.**  When the cached start still
took 1:21, the cache directory's own timestamps (buckets written, not
just read) said the boundary let the writes through and the lookup
missed — which pointed at the key, then at REFER — without a debugger.

## What went wrong, named as the session's

**The strace overrun was over-analysed from the fence.**  A runner
wrapped in strace ran 25 minutes past its 10-minute sitting; the cause
is that `kill "$pid"` cannot end a tracer ptrace-stopped on its tracee,
so the stop hung at `wait` with the lock held.  The session spent many
reads theorizing sitting_s and version skew before asking Henri to kill
the server, which resolved it in one line.  A live process the session
cannot see into is Henri's hand sooner, not the fence's guesswork
longer.  It is carded on `session-program` (§09:37) as the
watcher-heartbeat gap — real, and not the wrapper's fault alone.

**A false alarm was echoed as agreement.**  When he said "not going
idle in time" on the *clean* run, the session first treated it as the
same hang; it had already stopped normally at 09:36:14.  His own "I was
just too hasty again" is the same shape from the other side — the
lesson is to read the state before naming the failure, which the mtimes
then did.
