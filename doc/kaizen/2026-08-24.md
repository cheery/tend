*Written by the session at the end of the sitting, at Henri's ask:
"let's do kaizen and pack it up."  What was found, what went wrong, and
what should change — each with the evidence that pays for it, in this
tree where possible.  Not a journal; tend has none yet.*

## What the day was

Empty board at the start (one contract test, audit red on 4 of 10

## What went right, and why

**Mechanisms travel; the day proved the vision line.**  `pre-commit.sh`,
`limit.sh`, `test_limit.py` and `test_precommit.py` were carried from
gestate nearly byte-for-byte and worked on arrival — the header is the
only thing that had to be rewritten, and it was rewritten to say *where
this came from and why it is here*, which is the borrowing rule doing
its job.  Prose would have needed re-deriving; the mechanisms needed a
marker string.

**The demonstration rule paid on day one.**  The hook refused a
because-less card within an hour of being installed.  Practices arrive
tolerated; this one is owned here because it caught something.

**Enforcement edits found their pattern.**  Three times today a change
belonged to `.claude/settings.json`, which the fence denies a session.
What worked: the session writes the jq, tests it on copies in the
scratchpad (idempotence, deny rules intact, expansion), and Henri runs
one line.  Neither party did the other's job.  Worth naming as the shape
for every future enforcement edit.

**Henri's decisions arrived shaped, and were written down where they
bind.**  Gestate keeps its limit (portability); the memory shelf's
threshold (rules, or more than five tree-facts); reach as one dial held
by two hands.  Each went into the card's own fields the same hour, in
his words, so nothing is re-litigated tomorrow.

## What went wrong, named as the session's

**The refused commit's staging polluted the next one.**  After the hook
refused the dud card, its `git add -A` stayed in the index; the next
`git add <files> && git commit` committed the *whole index* — the dud
card included — and the working tree was green so the hook passed it.
The commit was rebuilt, but the class is worth a line: the hook checks
the working tree, not the index (gestate's deliberate gap), and here is
the first time the gap let something through.  *Candidate, not built:*
the hook could say, loudly and without failing, when staged content
differs from the tree it just checked.

**The session made gestate's `pgrep` bug again.**  `pkill -f 'while :;
do'` matched and killed the shell running it — the 2026-08-18 defect,
read about an hour earlier, remade.  Reading a post-mortem does not
install the reflex; a test or a tool does.  *Candidate:* nothing in
tend yet runs pattern kills; when something does, it gets a bracket
guard and a test that the pattern does not match its own line.

**A light load was believed because it was real.**  The first "real
caller" run — gestate's suite plus warm cargo — was a minute of
near-idle and was read for a moment as the incident.  A load is a
number (CPU-seconds, worst block), not a name.

**A test wrote a row into Henri's own sittings log**, checking that a
hook command expanded.  Small, confessed on the spot, and the general
rule holds: an instrument whose subject is a person is never run
against the live state to test something else.

## What the experiment taught that the experiment was not for

**An incident's reproduction decays with the tree.**  The 2026-08-18
load cannot be re-run because the suite it was made of is a minute now,
not twenty-five.  Keep-or-revert criteria phrased as *does it catch the
case that happened* have a shelf life; Henri's replacement — *how far
would it reach* — does not.

**A per-invocation budget does not bound a principal.**  The leash
budgets one command; twelve polling shells are twelve commands, each
under budget, together the incident.  What bounds a *session* is one
enclosure that its invocations nest inside — and systemd already has
the shape: a slice (the person's outer bound) containing scopes (each
invocation).  That is Henri's "user's leash bounds the session's" as a
cgroup tree, suspected, and it is where the reach design should start
looking before it invents a vocabulary.

## Countermeasures, delivered the same evening

Henri: *"deliver countermeasures to ensure your errors won't happen
again."*  One mechanism per error, each with the test that breaks it
on purpose first; none of them is a resolution to be careful.

| the error | the countermeasure | the test |
|---|---|---|
| a refused commit's staging polluted the next commit | `tools/pre-commit.sh` refuses when any staged path differs from the working tree it just checked — the staged-then-deleted dud is exactly that shape | `test_precommit.py::test_a_staged_file_deleted_from_the_tree_is_refused`, and the edited-since twin |
| `pkill -f` matched the shell that ran it | `test/test_selfmatch.py` — a gate over `tools/` and `test/`: every `pgrep -f`/`pkill -f` pattern starts with a bracket or a variable; and the detector itself is tested against the two shapes the session typed, including bundled `-af`, which its first version missed | `test_selfmatch.py`, both halves |
| a light load was believed because it was real | the leash ledger gets a `cpu=` column from the shell's own `times` — every invocation now carries its cost as a number | `test_leash.py::test_every_line_says_what_the_load_cost` |
| a test wrote a row into Henri's sittings log | `tools/limit.sh --hook` records nothing unless the harness's JSON object is on stdin; run by hand it says so and touches neither state nor log (tend's copy only — the twin debt is in its header) | `test_limit.py::test_the_hook_run_by_hand_records_nothing` |

**What these do not reach**, said plainly: a pattern a session types
into a shell by hand is outside every gate in the tree.  The
countermeasure for that is a tool worth reaching for instead —
`tools/leash.sh` kills by scope and never by pattern — and a private
memory, which is a promise and is labelled as one.

## Henri's kaizen

> I learned how to generalise this discovery.  Now I understand you
> much better.  And I know how to provide different environments for
> different purposes.  Previously I thought this framing could be only
> applied to programming.  Now I know that anything mechanically
> error-correctible is in domain.

*The session's reading, suspected:* the criterion is operational, and
today's tree is the worked example.  A domain is in scope when being
wrong can be made visible by a check the worker cannot write to — a
hook, a counter, a ledger — and the blast radius of being wrong can be
bounded from outside.  Programming was the first such domain only
because its oracles were already cheap.  Where wrongness is visible
only to a person's attention, the mechanism is not a gate but a cord
(`card:cords.md`): the environment's job there is to make the question
reach somebody, capped.  Different environments for different purposes
is exactly which of those two a domain needs, and how much of each.

## What should change tomorrow

1. After any refused commit: `git reset` the index before the next
   real one, until the hook learns to say so itself.
2. The first tree-fact for the memory count is above: *per-invocation
   budgets don't bound a principal.*  It is written here rather than
   carried, which is what the count is for; `later/rules-and-memory.md`
   gets its first tally mark.
3. The next leash slice is not more options; it is the enclosure —
   one scope per session, invocations inside it — and it is measured
   the same way as today: CPU-seconds under and over.
