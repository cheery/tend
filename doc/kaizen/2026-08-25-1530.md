## What went wrong, named as the session's

**The correction landed in the working tree before the session noticed
who put it there.**  `git status` showed `tools/sandbox.sh` modified and
the first read was alarm — an unexplained change to a protected file.  It
was Henri's applied patch, benign, but the session staged a commit and

surprise in a protected path, always; the file being read-only to the
session is exactly why an unexpected change there deserves a look first.

## What should change tomorrow

1. keep governs reads only; write-scoping is the next Landlock bit, and
   it is not built.  A confined program can still write where the fence
   allows.  Name it when a caller needs it.
2. Nothing yet *makes* a program run under keep — the incantation is
   remembered, not enforced.  Wiring keep into the launch path (a
   program confined by default) is the step after write-scoping, and it
   touches the fence-hook, which wraps shell commands and not launches.
3. On any surprising change to a protected-set path: diff first, stage
   second.  A read-only file that moved is a question, not a given.
