# Kaizen, 2026-08-25 15:06 — a summary given the tree's own honesty

*Written because the lamp lit on `1782349`.  Henri: "Save them into
doc/summary/ ... make something that ensures they're kept updated.  They
are good."*

## What the sitting was

The two A4 sheets — the rules, and the interfaces — saved into
`doc/summary/` as plain markdown (canonical) beside the printable HTML,
and given the same hard/soft honesty the rest of the tree runs on:
`test/test_summary.py` refuses a commit if the sheets cite a path that
is gone or if their one live claim (the andon is not built, `cords`
blocked) stops holding; `tools/summary.sh` is a lamp that lights when a
mechanism the summary describes has a newer commit than the summary
itself.

## What went right

**"Kept updated" was read as the tree reads it, not as automation.**
The tempting reading is a generator that rebuilds the summary from the
code.  But prose is not derivable, and the tree's whole method is that a
mechanism must *say when it is wrong*, not pretend it cannot be.  So the
answer was a gate for the facts a test can check and a lamp for the
prose it cannot — the exact split of `fence.sh` (hard) and `kaizen.sh`
(soft), reused rather than reinvented.

**The lamp is commit-based, so it does not cry on a checkout.**  Same
lesson `limit.sh` and `kaizen.sh` paid for: mtimes lie across a clone,
commits do not.  And it clears the instant the summary is committed,
which the sitting saw happen — light before, fresh after.

**Plain files stayed canonical.**  The HTML is the pretty rendering, but
`rules.md` and `interfaces.md` are the source, because `vision.md` says
the person reads their work without the tool.  The sheet that lists the
plain files a person reads is itself a plain file.

## What went wrong, named as the session's

**The lamp shipped a bug that the pre-commit gate would not have
caught.**  `git log` prints nothing and exits 0 for a path with no
commits; the empty string reached `[ -gt ]` as "Illegal number".  It
was found by running the lamp by hand before committing — not by a
test.  `test_summary.py` checks the lamp parses and its `--hook` exits
0, but with the summary untracked the `--hook` path was silent and
green while the default path errored.  A test that runs the instrument
in the state it will actually meet (untracked, then tracked) would have
caught it; the one written tested the easy state.

**Two copies of the content now exist** (md and html), and only the md
is gated.  The html can drift from the md without anything saying so.
Acceptable for now — the html is a rendering a person regenerates — but
it is a second source of truth, and the honest note is that nothing
holds them equal yet.

## What should change tomorrow

1. If the html is regenerated often, it wants either generation from the
   md or a check that the two agree; until then, treat the md as the one
   that is true.
2. An instrument's test should run it in the state it ships in, not only
   the convenient one — the lamp's `git log`-empty bug is the reminder.
3. `tools/summary.sh --hook` is available and uninstalled; if the
   summary starts drifting in practice, that is the escalation, and it
   is Henri's line to add.
