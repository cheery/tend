## What went wrong, named as the session's

**A hook line was committed with its script unprotected, and the gate
could not see it.**  `install.sh --hooks apply` adds a line for
`install.sh --hook`; `install.sh` was not in `sandbox.sh`'s protected
set; the rule that every hooked script is protected lives in
`test_sandbox` and reads the *live* settings — so it went red only
after Henri applied the line, on a tree whose gate had said green.
Closed in `33f50f7`: a test that reads what `--hooks` *would* add and
checks it against `--protected` at commit time.  The shape is the
day's lesson: a rule that reads the live state is a rule the gate
sees one apply too late.

**`check` inherited `run`'s seat.**  Written to "read the grant as
`run` reads it", it also assumed `run`'s side of the fence — and said
✗ on a state directory that is read-only to a session by design.
Found by running it on the real nodes, not by a test; the test came
after.  A reader built from a runner carries the runner's
assumptions until one is shown wrong.

**The ABI probe named `keep.py` without the grant.**  `test_keep`
refused it; the replacement — keep itself confining `true` under the
grant — is a better check than the number it replaced.  The test was
right about more than it said.

**Small ones, each mine**: a test that assumed alphabetical order
where the set has its own; a `--check` run with a `cd` prefix that
nested and refused (the hook's exact-form rule working on its
author); a lamp line that said `sudo tend-install` before that
