# Kaizen — the second node's day one: three grants and a prompt answered, and a URL that was a guess

*Written because the lamp lit on the day-one commit.  Henri: "llama.cpp
not installed yet, the model URL was wrong, but I found that kind of
model from unsloth."*

## What the sitting was

The model in the tree (270 MB, gitignored before it could ride a `git
add -A`).  The measurement, with the binary already on the path:
`llama-server` under keep with the model readable, a state directory
writable and one port bindable — answered a prompt from inside the
fence over loopback, no denials.  Recorded on `work-environment-ai`
as the mediation frame's first half shown for the local program.

## What went right

**Measured before a launcher existed.**  The grant was a guess from
the 15:45 reading ("a server's reach is one port"); the run is what
made it a fact, and it took one command.  Had it needed more — a
cache directory, a config — the denials would have said which, and
the grant would have been widened by measurement.

**The model was ignored before it was in a commit.**  The 09:31 lesson
(`*.patch`), applied to 270 MB.

## What went wrong, named as the session's

**A URL from memory, handed as a command.**  The download line for
the model pointed at a path that does not exist; Henri found the
model himself.  The fence has no network, so the session cannot check
a URL — which is exactly why it should not hand one as if checked.
The honest form is the name of the thing and where to look, not a
`curl` line; or `--reach net` for the one command that checks it,
asked for out loud.

## What should change tomorrow

1. No URLs from memory as commands.  A name and a place; or a
   checked line.
2. The second node's shape is Henri's tiebreak: a second launcher of
   `node/run.sh`'s shape, or the grant beside the program — a
   three-line file — read by one launcher, served by one resolver.
   The measurement says three lines; the manifesto says the second
   program is what earns the general shape.
3. The lifecycle for a server: the request is the pull; the launcher
   watches the server's log for requests and stops it on idle.  Not
   built.
