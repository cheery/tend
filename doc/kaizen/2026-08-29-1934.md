## What went right, and why

**A count before a cause, and the count was a command.**  Henri asked
"would there be a way to catch the flake?" and the board's own record
answered: three flakes in six days, each real once counted, each
counted by hand or not at all.  The ledger and the shake are the 08-26
"1 in 10" as mechanism.  The first shake took one command to reach
the line a sitting had reached on 08-26 — 8 of 10, wall 7–9 s, load on
the line — and the second shake, after the rule changed, is what kept
the session honest: **the count did not move.**  Without it the window
rule would have landed as the fix.  That is the card's whole argument,
demonstrated on its own first evening.

**Chasing a "noise" line found a blind gate.**  Kaizen 1337's item 5,
`mutate.sh`'s `fatal: failed to write commit object` on every row,
"blocked nothing".  It was every gate row's "refused" coming from a
dud commit that could not *sign* — ssh signing from the global config,
a key the fence cannot see — never from the gate.  `green`'s finding
verbatim: the detectors are sound and the blindness is in the wiring.
Fixed in the harness (`-c commit.gpgsign=false`; no HEAD is exit 3),
two recorded gate breaks re-aimed at lines this sitting had rewritten,
and one row run for real: `COMMITTED — suite: red`, a verdict the
harness had never been able to reach.

**The fixture rule, applied within the hour, twice.**  The gate's first
run over the ledger left five fixture lines in the person's live
ledger; `conftest.py` now gives every test a ledger of its own, the
canvas's mechanism from the afternoon.  And the ledger tests' own
helper rewrote a file with two equal-length bodies in one second, and
pytest's rewrite cache ran one test's bytecode under the other's name
— the 08-26 seam with nothing on either side, caught on the first run
only because the sizes collided.  Both found by running.

## What went wrong, and whose

**The session's: a kaizen written mid-sitting.**  1918 was written at
19:2x with an hour left on the clock, because the session read "the
sitting ends" as "my builds ended".  The unit is the sitting
(`board/README.md`, 2026-08-27), and the lamp said so at every prompt
after; this file is the sitting's second kaizen, which the rule says
should not exist.  The instrument is the limit's own line — "62m left"
— read as the clock it is.

**The session's: a rule changed on a model, and the model was
incomplete.**  "Half a core per second under contention" explained the
8 of 10 well enough to propose two fixes and recommend one; the fix
was built, its own test went red then green, and the shake still said
8 of 10, stopped at exactly 2 s.  The window was a real defect (a 30 %
program is now busy) but not the load failure's cause.  What was
missing was the launcher's own tick reads under load, which nothing
writes where a test can read them; the card names that as the next
instrument.  Reasoning from a count is still reasoning.

**The session's, small:** the first "red check" of the tick and door
tests was green — a stash pathspec on an untracked directory — and
the session read the count before the setup's error line.  Named in
1918; repeated here because the second red check of the evening
(mutate) was done right, and the difference was reading the whole
output.

## What should change tomorrow

1. **One kaizen per sitting means one, written at the clock or at
   Henri's word** — never at the end of a build.  The lamp's "Nm left"
   is the clock.
2. **The launcher writes its tick reads** (`$STATE/ticks`, one line a
   second: ticks, delta, busy-at) so the shake's failure has a
   signature a test can read, and the 8 of 10 is decided by data, not a
   second model.  Then the shake again.
3. **A shake after every rule change to the launcher's idle** — the
   card's tool is now the card's habit.
4. **The tick's first night and the door's first turn** stand from
   1918, unchanged: `sudo tools/install.sh && tools/install.sh --tick`
   with a hold on the llm node; a key at `~/.config/tend/openrouter.key`
   and `tools/lead.sh llm --door openrouter`.
5. `mutate.sh` gets a row for the signing failure itself — a global
   config that signs with a missing key must read as exit 3, not as a
   sweep of "refused".
