and stopped by the sitting before a line of the card section was
written; the section quotes `stopped` rather than describing it.

"A mechanism a session cannot test is proposed, not declared" — and

here, so it went to the side that can land it, with its tests inside

## What went wrong, named as the session's

**A check that would have passed for the wrong reason.**  The first
sitting test asserted `"sitting" not in stdout` — and pytest's tmp
path carries the test's own name.  It failed loudly here, so it was
caught; but the same assertion in a test named otherwise would have
passed while checking nothing.  A check reads the line it means, not
the whole output.  That is 08-24's band lesson one size smaller: a
sensor is suspected until it is shown to fail when it should.

**Two setup slips, both shell prose.**  The scratch test copy's `ROOT`
resolved to the scratchpad (ten red tests, none real), and the patch
header came out `btools/launch.sh` from a `sed` on a path.  Both were
read and fixed in a minute; both are the strand batch 2 declined to
promote, and this sitting added two faces to it.  The reason not to
promote still holds — the catcher is faster than the rule — but the
count is now five.

**For a few commands `llm/grant` carried a word the tree's launcher
did not know.**  Between adding `sitting 10` to the grant and moving
it into the patch, the resolver hook on every command would have hit
"unknown word" on the llm node.  Nothing was pulled in that window;
still, a half-applied state existed because the grant was edited
before the question "what reads this file right now" was asked.

**Named, not fixed.**  The two `; true` in `test/test_leash.py` that
14:24 called a bug with an alibi are still there; this sitting wrote
a line about them and did not touch them, because the leash is not
this sitting's and a blind edit to a sensor's test is the thing the
batch was reading about.  It is written as a debt, not a finding.
