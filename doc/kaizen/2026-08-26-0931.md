*Written because the lamp lit on `70212c3`.  Henri: "sandbox-limit.patch

## What the sitting was

A one-commit cleanup.  The self-card commit `a9a9958` used `git add -A`,
and `sandbox-limit.patch` — a handoff artifact Henri had already applied,
sitting untracked at the root — was swept in with it.  The limit note it
carried was correctly in `tools/sandbox.sh`; only the patch file was
stray.  Removed it and added `*.patch` to `.gitignore` so it cannot
happen again.

## What went right

**The stray was caught by looking, the moment it could be.**  When
Henri said the patch was applied, checking `git status` showed `D
sandbox-limit.patch` — a tracked deletion where an untracked file was
expected — and that one letter said the file had been committed. The
mechanism (ignore the class) is the fix, not a resolution to stage more
carefully.

## What went wrong, named as the session's

**`git add -A` stages everything, including what is not the change.**  I
have handed Henri several patches this session and removed each before
its commit — except this one, which he applied on his own clock, so it
was in the tree at a moment my `git add -A` did not expect.  The
countermeasure is the `.gitignore` line, not vigilance: a handoff
artifact that cannot be committed is one I cannot forget to remove.  The
same shape as every countermeasure this tree keeps — make the wrong
thing impossible for a mechanism, not unlikely for a person.

## What should change tomorrow

1. `*.patch` is ignored now; patches for Henri's hand live at the root
   and are invisible to git, which is what they are.
2. When a commit follows a step Henri did on his own clock, `git status`
   before `git add -A` — his change and a stray can arrive in the same
   untracked moment.
3. The self sitting is fully closed, tree clean.  The board's next move
   is Henri's: `keep`'s launch-path-for-any-program, `kaizen-ingestion`
