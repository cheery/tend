## What went right, and why

**The finding came from a grep nobody asked for.**  The three tools arms
had failed and the obvious reading was "thinking did not help."  What
made the sitting worth anything was checking whether the reasoning
channel had carried anything at all — `grep -c " T: "` across the six
`replies` files — which split the six into three with a `T:` line and
three without, on the same flag, the same door, the same model.  That one
line turned "thinking did not help" into "thinking works and tools
disable it", which is a different fact with a different fix.

**The defect was assigned to the right side.**  That qwen stops emitting
reasoning when handed tools is not tend's and cannot be fixed here, and
the entry says so in its own `shows`.  What *is* tend's is that the
account asserted `thinking on` for turns with no thinking in them —
`compare.py:224` records the flag and never the fact, while
`deliver.sh:272` already reads the channel and prints a `T:` line only
when it is non-empty, so the tool knows and does not say.  A cap that
says nothing is silent; this one asserts, and that is why it is an
F-number and the model's behaviour is not.

**His evidence was recorded as his.**  "These all models I've tried
overthink into the context and fail to run" went onto the card as
relayed, not measured — batch 1's form ([[2026-08-25-0744]]) — with what
it does and does not settle written beside it.  It reorders the card's two
statements without closing either.

had been typed that morning, and **the first version refused two rows it
should not have**: a measurement, because the `x` in `open('x')` was read

## What went wrong — named as mine

**I called this defect silent, and it had been shouting at me.**  When I
offered Henri the two shapes I described the harness rewrite as a silent
corruption whose only catcher is reading the file back.  Writing the card
forced the split, and the split says otherwise: when the brace holds
something that is not a valid environment variable name the harness
**prints** `Invalid environment variable name evaluates to an empty
string` as it drops it, and **all five faces of the previous sitting were
that kind**.  The warning was in my own tool output three times.  I read
it, and twice the very next thing I did was write more prose about the
bug.  Only the `consult.sh` case — a valid name, merely unset — is truly
silent.

So the sentence I gave him was wrong about the defect *and* flattering to
me: it described a thing that could not be caught, when the truth is a
thing that was caught and worked past.  The card carries the corrected
version with the withdrawn one beside it, and the correction is what made
day one's argument sound — a louder warning cannot be the fix, because
one exists and it is not what failed.

**The first boundary was written from reasoning and it was wrong twice in
ten lines.**  The table that corrected it took one command.  Nothing was
committed wrong, so this is process working rather than a defect — but
the order was backwards, and the table was the cheaper thing to write
first.
