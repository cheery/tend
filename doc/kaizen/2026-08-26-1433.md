# Kaizen — the tree row measured by what it writes, and a git count that could not tell a hand from a session

*Written because the lamp lit on `bf9e16a`.  Henri: "do the tree row
measurement."*

## What the sitting was

The last row of `keep`'s session half, measured with the other
question — what the purpose *writes* — in two halves: 120 commits by
path, 310 fenced commands by write target.  Written by the work:
board, doc, test, the unprotected tools and node, the root documents,
`.git`.  Never a session's write target: `.venv`, `node/state`,
`.claude`.  The finding: the only write the session makes that is not
the work is the node's, and closing it is the resolver outside the
session's write access — named on both cards, not built.

## What went right

**The question was changed before the measurement, not after.**  "What
does the purpose read" would have said *everything* and closed
nothing; the 14:12 kaizen said so and proposed the write side, and the
write side found the one directory that is a program's and not the
session's.  Two rows narrowed by reading; the third by writing.

**The two halves checked each other.**  `git log` said sessions had
committed `.claude/settings.json` eight times; the ledger said zero
fenced writes to it.  Neither alone was the answer — the commit carries
the session's trailer and Henri's hand's edit — and the card says both
numbers and why they differ.

## What went wrong, named as the session's

**The first two passes were wrong and I read past them.**  Pass one
counted commit-body prose as file paths ("mv/ 1", "the .git/ 1") and
`sed` expressions as write targets ("s/ 127"); pass two crashed on a
trailer format.  Three runs to one clean count.  The 13:42 kaizen's
lesson — a count read from a format not checked — was re-learned on
a different format the same afternoon.  The countermeasure the ledger
got (a parser as a tool) is what git needs too: the by-author,
by-path count is the second time `git log --name-only` has been parsed
in a heredoc today, and by the tree's rule that is a tool on the next
ask.

**A measurement's limit was found late.**  The ledger cannot tell a
write in the tree from the same relative path inside a scratch copy
after `cd`; the "50 protected-set write targets" would have been an
alarm if not read.  It is named on the card as a limit, which is the
honest place, but it should have been the first thing checked when the
number appeared, not the last.

## What should change tomorrow

1. `git log` by author-kind and path is a tool on the next ask;
   `tools/ledger.py` is its shape.
2. `.venv` read-only is a free bind; it waits so it lands with the
   resolver decision as one row.
3. The resolver as a hook on the person's side of the fence — started
   by a pull line, confined by `run.sh`, outliving the command — is the
   next slice of both cards, and it is Henri's to want.  Its cost
   (when it runs, what the leash says) is measured before it is built.
