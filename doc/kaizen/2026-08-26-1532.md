## What went right

**The order held.**  The card said the bind had to land after the
hook, or a session's pull would never be served; the hook has served
pulls since 15:03 and the race is closed since 15:24; the bind comes
last.  Three sittings in the right order, each measured before the
next.

**The patch was read for its content.**  Five greps for the five hunks
I meant — two binds, two probes, two tests — before the commit, which
is the 15:09 countermeasure applied once.  And "red against the old
file" was not done by copying the old file over the scratch copy this
time; the bwrap test is Henri's to run red-then-green, since it cannot
run here at all.

**The first pull ever is provided for.**  A read-only directory with
no pull file would refuse the first pull; the person's side creates
both before the fence.  Found by asking what the bind does on a fresh
clone, not by a failing run.

## What went wrong, named as the session's

bwrap test and the three probes run only from Henri's seat.  A fence

`--check` is the execution, as it was for the state row (which went
down once) and the trees row (which did not).  If it goes down, the
probe that says so is in the patch.
