## What went wrong, named as the session's

**The panel shipped with a bell that does not ring.**  `curses.beep`
was written as "the sound" without checking it makes one; terminals
mute BEL by default, and the fix (play a real tone through `pw-play`)
was available from the andon's own code the whole time.  A cord's sound
is not written until something is heard — the same lesson `silent-cord`
carries, remade one layer up.

**The panel's day one did not integrate with the record it reads.**  It
counted `ring` and not `ring-failed`, so on its first real fenced ring
it would have shown the question and stayed silent — the reach-free path
half-built.  Reading `tools/andon.sh`'s own log vocabulary before
writing the reader would have caught it; the test did instead.

**A commit was reported refused when the gate had passed.**  `bc55a1d`
was called transient and retried; it committed clean.  A gate result
read in haste is the same haste the tree keeps warning about — read the
line before naming the failure.
