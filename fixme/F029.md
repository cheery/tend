## What it cost

Nothing read wrong by anyone before today: the one path ever set was
the default.  What it would have cost is the row's own purpose — the
person binds a directory for a session and the session says "I cannot
see it" indefinitely, or worse, reads a session's "it is not there"
as a fact about his disk.  It cost this sitting its first half hour:
the file Henri wanted read (`~/misc/lineaarilogiikka-kieli-keskustelu.md`)
was still unread when this entry was written, and the first reading of
the symptom — that the harness snapshots its hooks at session start —
was wrong and was said to him before the restart proved it wrong.
That reading is recorded here so its shape is recognisable: a true
fact about the harness (it does capture hooks at start) offered as the
cause of something it did not cause.

## The fix

`tools/fence-hook.sh` writes `TEND_TREES` into the rewritten command
when the hook's environment has it set, quoted through `jq @sh`, and
set-empty crosses as `TEND_TREES=''` because `tools/reach-allow.sh
--trees ""` is a bind of none and unset is the default again.  Nothing
else on the hook's line is forwarded: `TEND_REACH_ALLOW` is the hook's
own to read, and the hook is the boundary that reads it.

The test runs the hook with the variable in its env and reads the
command it hands back — the seam, not either side of it.  Not tested
from this seat: the sandbox actually binding the directory the command
names, which needs bwrap outside the fence and is the read that
resolves this entry.
