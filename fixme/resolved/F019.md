## What it was, and why it is two fixes

**The real defect.**  The watcher's job is to start the pulled node the
instant the program grabs the edge.  It detects the grab by polling with
a non-blocking exclusive `flock -n` — which fails while the program holds
its shared lock, and succeeds while the edge is free.  The failure mode:
if the program grabs and releases faster than one 0.05 s poll (a stub
answers in microseconds; so does any pull whose whole conversation is
quick), the watcher never observes the lock.  Its `while` condition keeps
succeeding, so it runs the full 1200 polls — 60 s — and only then reaches
`flock -n || serve`, where the edge is now free, so serve is never even
called.  So a fast pull got two wrongs: the pulled node was not served at
the lock (the tick would have to catch it later), and for 60 s the edge
read as intermittently held to everything that tests it — the panel's row
(`_lock_held`), the resolver, `pulled_by`, and this test.

The fix: `run` collects the watcher PIDs and, once the program has
exited, kills and waits them.  A watcher that caught the lock ran serve
and exited long before this (serve runs while the program is still up); a
watcher still alive here is one that missed the lock, and its pull is
already over, so it has nothing left to serve.  This removes the 60 s
spin and its lock disruption.

**The residual, and the test.**  Killing the watcher can orphan its very
last `flock` child for a microsecond, and — more fundamentally — the
whole tree tests these advisory locks with a momentary exclusive
`flock -n true` (`pulled_by`, `_lock_held`, `status`, `serve`).  Any two
of those can collide for the microseconds one holds the lock to test it.
Every reader in the tree already tolerates this by re-reading; only the
test asserted once.  So the release assertions now poll
(`wait(lambda: not locked(edge))`): the edge *is* released — a reader's
microsecond test-lock is not the program holding it — and a genuinely
held edge still fails, because `not locked` never comes true and the wait
times out.

**Measured.**  Before: ~1 in 40 immediately after return in the harness,
and three live flakes in one session.  After the watcher kill: the
harness dropped to a sub-millisecond orphan window; with the polling
assertion the gate shook **0 of 25 under load, 8 cores burning**.
